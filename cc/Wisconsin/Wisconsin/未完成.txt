2. 补上 dst.is_empty() 的前置检查
你的意图是对的：dst 必须预留最后一个位置给 0 终止符。在这个契约下，i + 1 >= dst.len() 恰好是“写 c 之前，保证后面还留得下 0”，所以对非空 src 来说逻辑是成立的。我之前说“过早失败”，是按“不需要终止符”的语义讲的；你这里明确要终止符，那这个检查就是对的。先纠正一下。

非空 src 的情况：正确

设 dst.len() = L。循环里要求 i + 1 < L，即 i <= L - 2，写完后 i_new <= L - 1。循环结束时 i <= L - 1，所以 dst[i] = 0 安全，且不会覆盖数据。长度刚好 needed + 1 时也能通过：

```text
src 需要 3 个码元，dst.len() = 4
i=0: 1 >= 4? 否 → dst[0]=c0, i=1
i=1: 2 >= 4? 否 → dst[1]=c1, i=2
i=2: 3 >= 4? 否 → dst[2]=c2, i=3
循环结束 → dst[3]=0   ✓
```

长度不够时也会正确报错。

唯一的漏洞：空 src + 空 dst → panic

```rust
let src = "";
let mut dst: [u16; 0] = [];
encode_path_utf16(src, &mut dst);  // 循环 0 次，i=0，然后 dst[0] = 0 → 越界 panic
```

循环一次都不执行，i = 0，dst[0] = 0 直接索引越界。函数会 panic，而不是返回 Err。 一个返回 Result 的函数不应该 panic。

修复：进入循环前先检查至少有一个位置

```rust
fn encode_path_utf16(src: &str, dst: &mut [u16]) -> Result<(), FileTransferError> {
    if dst.is_empty() {
        return Err(FileTransferError::BufferTooSmall);
    }
    let mut i = 0;
    for c in src.encode_utf16() {
        if i + 1 >= dst.len() {
            return Err(FileTransferError::BufferTooSmall);
        }
        dst[i] = c;
        i += 1;
    }
    dst[i] = 0;
    Ok(())
}
```

这样：

src dst 行为
空 空 Err（不再 panic）
空 长度 ≥ 1 dst[0]=0，Ok
非空 够 needed+1 正常写入 + 终止符，Ok
非空 不够 Err

另一种更直观的写法：先算总需求

```rust
fn encode_path_utf16(src: &str, dst: &mut [u16]) -> Result<(), FileTransferError> {
    let needed = src.encode_utf16().count() + 1;  // +1 给终止符
    if dst.len() < needed {
        return Err(FileTransferError::BufferTooSmall);
    }
    for (slot, c) in dst.iter_mut().zip(src.encode_utf16()) {
        *slot = c;
    }
    dst[needed - 1] = 0;
    Ok(())
}
```

代价是多遍历一次 src，但边界判断集中在一处，更不容易漏掉空输入；而且 dst[needed - 1] 在 dst.len() >= needed >= 1 下一定安全。

顺带一提

FileTransferError::IoError 用来表示“缓冲区不够”语义不贴切，建议单独 BufferTooSmall，调用方才能区分“真的 IO 失败”和“你给的 dst 太小”。

结论：你的核心逻辑（预留末位、循环内 i+1>=len 检查）在“必须写终止符”的前提下是对的；补上 dst.is_empty() 的前置检查，就不会有 panic 了。
