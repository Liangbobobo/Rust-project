
## win官方展开器RtlVirtualUnwind遇到没有.pdata的叶子函数情况

叶子函数:如NtAllocateVirtualMemory没有执行sub rsp,X ,也没有保存寄存器,所以调用它的上一级函数的返回地址,物理上必然就在当前`[rsp]`栈顶.还是没有理解,需要图,一般的函数从rsp开始的结构包括返回地址和叶子函数的栈帧结构返回地址结构分别是怎样的.  
展开器只要继续执行`Next_RIP = *RSP; Next_RSP = RSP +8`,就能把控制权交给下一层.

根据微软win64 abi展开规范,当系统函数RtlVirtualUnwind(RIP, RSP)->RtlLookupFunctionEntry(RIP)查表或edr栈回溯探针,对当前rip进行分析时遇到叶子函数返回null时:
1. 叶子函数不会让展开失效,因其不改动rsp的物理特性,展开器能够读取`[rsp]`切换到上一层(uwd项目中的firstframe)
2. uwd/Mariana 中,整个四层伪造栈从叶子函数开始,经由firstframe接入.pdata轨道,一路至RtlUserThreadStart.


## 一般非叶子函数栈帧视图

| 内存地址 (64位) | 栈槽内容 (QWORD / 8字节) | 物理含义与说明 |
|---|---|---|
| RSP + 0x58 (顶部) | [ 本函数的返回地址 (Return Address) ] | 这是父函数执行 call 时压入的返回地址！ |
| RSP + 0x50 | [ 保存的旧 RBP (Saved RBP) ] | Prologue 中执行 push rbp 保存的旧帧指针 |
| RSP + 0x48 | [ 保存的旧 RBX (Saved RBX) ] | Prologue 中执行 push rbx 保存的寄存器 |
| RSP + 0x28 ~ 0x40 | [ 本地局部变量 (Local Variables) ] | 本函数内部计算使用的局部变量数组/结构体 |
| RSP + 0x00 ~ 0x20 | [ 32 字节影子空间 (Shadow Space) ] | 当前 RSP 停在这里！<br>• [RSP + 0x18] -> 保留给 R9<br>• [RSP + 0x10] -> 保留给 R8<br>• [RSP + 0x08] -> 保留给 RDX<br>• [RSP + 0x00] -> 保留给 RCX<br>Windows x64 ABI 强制规定：调用任何子函数前，必须在栈顶留出 32 字节供子函数把寄存器参数写回内存（Home） |

声明周期:
1. 父函数执行call压入返回地址
2. 函数执行prologue:push rbp(rsp-8)  push rbx(rsp-8)  sub rsp,0x48(开辟局部变量+32字节影子空间)
3. 展开器RtlVirtualUnwind扫描时,必须去查看它在.pdata节中的UNWIND_CODE展开码.按照展开码的指引,跳过0x48的栈空间,再依次pop rbx pop rbp 最后在rsp+0x58处找到真正的返回地址

## 叶子函数栈帧视图

| 内存地址 (64位) | 栈槽内容 (QWORD / 8字节) | 物理含义与说明 |
|---|---|---|
| RSP + 0x08 | [ 调用者的第 5 个参数或父栈数据 ] | 这是上一层函数的栈空间 |
| RSP + 0x00 | [ 上一级调用者的返回地址 (Return Addr) ] | ◄── 【当前 RSP 停在这里！】 |

生命周期:
1. 上层函数执行 call ntdll!NtAllocateVirtualMemory
2. cpu硬件自动把下一条指令的地址(返回地址)压栈,rsp-8,`[rsp]`存入返回地址
3. 进入NtAllocateVirtualMemory内部:执行mov r10,rcx; mov eax,18h; syscall; 整个过程rsp不动
4. 展开器RtlVirtualUnwind扫描时:发现没有.pdata;之后直接读取`[rsp]`拿到返回地址,然后rsp+=8,跳回上一层
