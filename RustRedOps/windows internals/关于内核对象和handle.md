# 关于win64下内核对象和handle

类比Linux的一切皆文件,win64下绝大多数系统资源,都是对象管理器(Object Manager)管理的内核对象(结构体),且在用户态通过句柄来间接表示.

**没有句柄的核心资源:有些核心资源不需要,也没有句柄.操作这些资源时拿到的是直接内存地址或硬件状态**
1. 物理/虚拟内存页面:如调用NtAllocateVirtualMemory申请内存,内核返回的是一个裸指针(代表一个内存地址).这块内存页本身不在句柄表中占位,也没有对应的句柄(虽然用于共享内存的Section对象有句柄,但映射的内存数据本身没有句柄)
2. TEB/PEB:这是用户态可以直接读写的内核/用户共享结构体.它们不需要通过句柄表查表访问,通过GS段寄存器(如`gs:[0x30]`)就可以拿到它们的内存指针进行访问.
3. CPU寄存器与硬件状态:CR3,RIP,RSP等寄存器是物理硅片上的状态,它们没有任何句柄代表的结构体.

**除了上述底层的物理/内存基础设施外，Windows 的所有系统资源（Executive Resources），全部都是句柄代表的内核对象结构体**:
1. 进程与线程 (_EPROCESS / _ETHREAD)
2. 同步原语 (_KEVENT / _KMUTANT / _KSEMAPHORE)
3. 文件与通信 (_FILE_OBJECT / 管道 / 邮槽)
4. 访问控制 (_TOKEN 令牌)
5. 注册表键 (_CM_KEY_BODY 注册表键体)
6.  内存共享映射 (_SECTION 节区对象)

**这些不同内核对象的共同点和不同点:**

以上,win在c语言层面时献礼一套及其彻底的面向对象编程(OOP)的设计:

一. 统一的基类(_OBJECT_HEADER),即统一的对象头:所有内核对象结构体在内存中的头部,都必须包含一个统一的对象头.这类似于c++中的基类.每个内核对象在非分页池中分配其真正的结构体数据(如 _EPROCESS)前,必定紧挨着一个**统一**的对象头?.该对象头结构体包含:
1. 指针引用计数(pointercount):记录内核中还有多少硬指针指向该对象
2. 句柄计数(handlecount):记录当前系统中有多少个打开的句柄指向该对象.意思是同一内核对象,可以被打开多次?具体的例子
3. 对象类型(typeindex):指向一个描述该对象类型属性的结构体(_OBJECT_TYPE),内核以此得知这是个进程还是文件
4. 安全描述符(SecurityDescriptor):存储ACL(访问控制列表),规定哪些用户或组,拥有读,写,执行权限

二. 用户态访问必须通过私有句柄表(_HANDLE_TABLE)

用户态程序(ring 3)绝对无法拿到任何内核对象的真实物理指针.必须先通过系统调用(如 NtOpenProcess)申请权限,在当前进程的私有句柄表中登记该对象,获取一个整数值(即handle)作为访问索引

三. 统一的生命周期和托管机制

所有内核对象的生命周期由引用计数驱动:当用户态程序调用 NtClose 关闭句柄时，内核将该对象的 HandleCount 减 1;只有当 HandleCount == 0 且 PointerCount == 0 时，内核对象管理器才会调用ExFreePool 物理销毁该对象在内存中的数据

四. 安全访问控制与访问掩码（ACCESS_MASK）

所有内核对象都受 Windows安全系统的统一制约。在打开句柄时，你必须提交访问掩码。内核会拿着你的Token（令牌）与对象头中的安全描述符进行比对，决定是否发给你句柄


**不同之处**

不同内核对象的设计用途不同，它们在调度机制、命名空间和内存管理上表现出显著不同.主要有:
1. 可等待对象（Waitable Objects） vs 不可等待对象:这是内核对象最关键的物理分水岭。它决定了该对象能否被放入NtWaitForSingleObject 进行等待.
    * 可等待对象(同步对象),如_KEVENT,_EHTREAD等这类对象的内核结构体的第一个成员,必须是名为Header且类型为 _DISPATCHER_HEADER（调度器请求头）的结构体.这个结构体包含一个SignalState和一个等待链表.如事件（Event）、互斥锁（Mutex）、线程（Thread，死亡时变绿）、进程
    * 不可等待
    * 不可等待对象:结构体头部没有 _DISPATCHER_HEADER 结构.如访问令牌（Token）、注册表键（Key，对应_CM_KEY_BODY）、物理内存映射节区（Section）。如果你对一个 Token句柄调用 NtWaitForSingleObject，内核会直接返回状态码STATUS_OBJECT_TYPE_MISMATCH（类型不匹配）
2. 命名空间行为差异（Named vs Anonymous）
    * 具名内核对象(Named Objects):事件（Event）、互斥锁（Mutex）、映射节区（Section）可以拥有全局名字（如Global\MyDecoyMutex）。它们会被挂载在对象管理器的全局目录树中。其他进程可以通过名字打开相同的对象
    * 匿名内核对象:进程（Process）和线程（Thread）没有全局名字，只有数字ID（PID/TID）。你无法通过名字打开一个进程，必须通过 PID 查表;令牌（Token）是隐秘的，它只挂载在进程或线程结构体上，没有对象命名空间路径
3. 内核内存池分配差异
    * 非分页池（Non-Paged Pool）：像线程（_ETHREAD）、进程（_EPROCESS）、事件（_KEVENT）这些涉及系统高度调度、硬件中断和 CPU上下文切换的核心对象，必须常驻物理内存，绝对不允许被交换到磁盘分页文件中
    * 分页池（Paged Pool）：像注册表键体（_CM_KEY_BODY）或部分大容量文件映射，允许在系统物理内存紧张时，被操作系统置换（Page Out）到硬盘的 pagefile.sys中，以腾出物理内存
