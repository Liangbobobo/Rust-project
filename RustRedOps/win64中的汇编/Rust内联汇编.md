
# Rust原生内联汇编(通过core::arch::asm!实现)

Rust 1.59官方稳定了core::arch::asm!

允许在Rust源码中直接嵌入cpu原生机器指令,由Rust编译器(基于LLVM后端)将Rust变量与CPU的物理寄存器精准绑定

1. 默认采用Intel汇编格式:mov 目标,源 但其语法中指令动作,如mov 是intel的硬件指令语法;变量交接,如in lateout options等是rust编译器指定的跨界通讯语法.
2. 使用汇编指令模板,其中{}作为寄存器占位符

## Rust内联汇编的输出修饰符out和lateout

Rust内联汇编提供了两种输出修饰符out和lateout

out:告诉编译器,这个输出寄存器在汇编代码一开始执行时,就可能被写入或破坏  
编译器绝对不敢把输入变量in和输出变量out分配给同一个物理寄存器,必须强行占用两个不同寄存器.如rax作输入,rdx作输出

lateout:延迟写入/晚期占用.告诉编译器直到所有的输入变量都被读取完毕后,这个输出寄存器才会被写入  
及其激进的寄存器复用优化:编译器发现既然输入变量读完就没用了,那么把输入变量和输出变量分配到同一个物理寄存器是安全的.

Example:
```asm
out(reg) out（强制使用 2 个寄存器）：

mov eax, 60h          ; rax 存放 offset (输入)
mov rdx, gs:[eax]      ; rdx 存放 out (输出) -> 消耗了 RAX 和 RDX两个寄存器

lateout(reg) out（巧妙复用 1 个寄存器）：

mov eax, 60h          ; rax 存放 offset (输入)
mov rax, gs:[eax]      ; CPU 先用 eax 寻址读取内存，读完后直接把结果写回rax！-> 仅消耗 RAX 一个寄存器


```

## Rust内联汇编的输入修饰符in

`
in(reg) offset
`

in属于Rust内联汇编核心的流向修饰符  
物理含义,告诉llvm编译器,这是一个只读的输入操作符,在cpu执行引号内的第一条汇编指令前,必须把数据提前装填到物理寄存器中.  
底层时序保证:编译器在进入汇编块的前一刻,自动生成一条预备指令(如 mov eax,60h).编译器确保cpu运行到`"mov {}, gs:[{:e}]"`时,寄存器里已经放好了offset的值

reg:Rust / LLVM 寄存器类规范  
告诉编译器,分配一个64位通用寄存器容纳这个输入数据.

类型对齐:  
1. 输入参数是offset: u64（64 位无符号整数）,(reg) 刚好对应 x86_64 架构下标准的 64 位寄存器（rax ~ r15）
2. 数据的类型位宽与硬件寄存器的物理位宽100%自然对齐，无需任何截断或扩展指令

## Rust asm! 的 4 大数据流转模式

| 约束关键字 | 数据流动方向 | 物理时序特点 | 经典应用场景 |
| --- | --- | --- | --- |
| in(reg) x | Rust → 寄存器 | 进入汇编前装填好数据（只读） | 传入偏移量、系统调用号（SSN）、API参数 |
| out(reg) y | 寄存器 → Rust | 汇编执行中写入，不可与输入共用寄存器 | 接收普通返回值 |
| lateout(reg) y | 寄存器 → Rust | 汇编最后一步才写入，允许与 in 共用寄存器 | 极度优化寄存器占用的返回值读取 |
| inout(reg) z | Rust ↔ 寄存器 | 读写共用同一个变量（先读入，修改后再写回） | 原地递增、循环计数器、标志位修改 |
